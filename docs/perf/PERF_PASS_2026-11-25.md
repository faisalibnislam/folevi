# Performance pass, 2026-11-25

End-to-end performance work for every platform (web, iPhone/iPad, Mac, Android, Windows). Coordinated from one
session; each area runs in its own session with its own pull requests.

## Owner's decisions

- Platforms: web, iPhone/iPad (Capacitor, PR 66), Mac (AppKit web view), Android (PR 69), Windows/Linux (PRs 58, 65).
- Priorities, all four: startup and first load; opening and typing in notes; scrolling and lists; backend cost and
  memory.
- Small visible changes are fine (smaller pages, a placeholder a moment longer, screens loaded on demand). No design
  changes, no removed features.
- Targets, measured before and after: LCP < 2.5 s, INP < 200 ms, CLS < 0.1, note open < 300 ms, 60 fps scrolling,
  no memory growth from opening notes.
- Test data: a generated library of 5,000 notes, 200 folders, 2,000 tasks, some long notes with images. Never the
  owner's real library or data.
- No real devices: Simulator, emulator and browser measurements only; say which results are unconfirmed on hardware.
- Releases: ask the owner before every TestFlight, Mac feed or Play upload. Web changes go live when their PR merges
  (auto-merge once the 12 required checks pass).
- Unmerged shells: shell-specific fixes go with each shell's branch; shared web and backend fixes go to `main`.
- Production Convex: read-only only. `.mcp.json` adds `convex-prod-readonly`, the Convex MCP server pinned to
  production with only `status`, `tables`, `functionSpec`, `logs` and `insights` enabled (no `data`, `env*`, `run`,
  `runOneoffQuery`). It needs the main checkout's Convex link (`.env.local`), so pass the main checkout as
  `projectDir`.

## Production today (insights, 2026-11-25)

No read-limit or bandwidth warnings. Only small OCC retries: Better Auth's `rateLimit` table (updateMany 21,
create 7, deleteMany 7), `session` (2), `restApi.js:limit` on `rateLimits` (9), and one each in the nightly
`presence.cleanup`, `tasks.processReminders`, `maintenance.runDeletionJobs`, `e2ee/reminders.process`. The `logs`
tool only streams new entries, so past runs can't be ranked. Gains will come from making a 5,000-note library scale.

## Backend findings (static audit, not yet confirmed at runtime)

Root cause: every `documents` row carries the note's full `searchText` (up to 32,000 characters,
`packages/editor-schema/src/search.ts:83`) plus `excerpt` and `preview` (`convex/schema.ts:360-377`), so any list,
count or title read pays for the whole note.

1. HIGH `organization.index` (`convex/organization.ts:149-182`, `folderRow` `:115-117`): up to 2,000 full rows per
   folder, always on in the Sidebar ("Recent" folder sort), Folders page, iPhone Home. Likely over the read limit at
   5,000 notes; re-runs on any edit in any folder. Fix: per-folder `documentCount` and `lastEditedAt` (or
   `@convex-dev/aggregate`), restricted pages counted through an index, 5 preview rows from a summary table.
2. HIGH `organization.recentFolders` (`:189-219`, Home, HomePicture): same fix.
3. HIGH `documents.list` (`convex/documents.ts:192-253, 287-317, 322-346`): starred, folder and tag views read the
   whole set to show one page; "all"/"unsorted" use `.filter()` over a sort index. Fix: page `by_folder_listed`
   directly, stars newest first with `take(n)`; split note text into a `documentText` table holding the search
   indexes; add a `listed` field to the sort indexes.
4. HIGH `tasks.list` / `tasks.range` `present()` (`convex/tasks.ts:45-79`): a full note row per task for its title
   and icon; `take(1000)` makes counts wrong past 1,000 open tasks. Fix: title and icon on the task row, counts kept
   up to date, paginated lists.
5. MEDIUM-HIGH `organization.draftCount` (`:316-335`): up to 5,000 full rows, always on. Fix: maintained count.
6. MEDIUM-HIGH `changes.list` (`convex/changes.ts:71-119`): 60 notes plus their blocks, re-runs on every push.
   Fix: per-person unseen-changes row or `lastOtherEditSeq`.
7. MEDIUM `nextSeq` (`convex/lib/seq.ts:30-55`) and the per-push `rateLimits` patch (`lib/rateLimit.ts:101-114`):
   one hot row per scope; `sync.head` wakes every tab on each push. Fix: sharded rate limiter, debounce pulls.
8. MEDIUM device copy (`sync.manifest`, `convex/sync.ts:216-234`, `DeviceCopyRunner.tsx`): whole library per
   browser profile, pages near the read limit.
9. MEDIUM `searchDocuments` (`convex/search.ts:111-155`): ~150 full rows per keystroke, live subscription in 5
   places. Fix: fewer hits, summary table, one-off query.
10. LOW block deletes and `blocks.deleted` load every block; `sharing.sharedWithMe` fetches one by one; `withExtras`
    per row.

Order: split note text out (3), folder counts and drafts count (1, 2, 5), task title and counts (4), cheaper
Changes (6).

## Native shell findings (static audit, nothing measured yet)

Mac (`apps/mac`; PR 82 only changes `Tokens.swift`):
1. MEDIUM first window waits for a launch chain (`AppDelegate.swift:95-105`: rules, migrate, `Places.start`); content
   rules are compiled every launch (`Places.swift:363-366`). Fix: look the compiled list up first (as iOS does,
   `FoleviViewController.swift:223`); create the web view while the library opens.
2. MEDIUM runners start 1 s after launch (`Places.swift:94`) and compete with the first page load. Fix: after the first
   window's `didFinish` or ~5 s.
3. MEDIUM (energy) hidden-page timer throttling and process suppression turned off via private WebKit selectors for
   runners and every local-mode window (`Places.swift:74-87`). Fix: only for runners with work.
4. LOW Keychain read on the main thread at launch (`Places.swift:121`); `bridgeScript` rereads JS files per view
   (`WebViewFactory.swift:220-235`).
5. `apps/mac/scripts/perf.mjs` and `perf-scroll.mjs` measure the removed native UI; update before measuring.

iPhone/iPad (Capacitor, `claude/ios-feedback-b1307a` / PR 66):
1. HIGH if still growing: note-page memory (fix on main, `components/iphone/transitions.ts:181-188, 344-351`); the
   Simulator `footprint` re-run is pending (baseline 172-183 MB, `docs/MOBILE.md:70`). An interrupted transition may
   not release.
2. MEDIUM every library read/write is JSON over Capacitor's message handler (`bridge/mobile-bridge.js`,
   `Host/HostBridge.swift:104-196`); copy the Mac's `_bridge` scheme route for large payloads.
3. LOW-MEDIUM synchronous Keychain work before first load (`FoleviViewController.swift:130`, `AppDelegate`); the splash
   waits for window `load` (`mobile-bridge.js:544-555`), hide it on the shell's first frame.
4. Unsure: Cache-Control on `capacitor://` assets.

Android (Capacitor, `claude/android-capacitor-197cf4` / PR 69):
1. MEDIUM-HIGH `Application.onCreate` main-thread work (WorkManager, push, Keystore ciphers, Places migration) and a
   Keystore decrypt in `MainActivity.adoptLegacySession` (~`MainActivity.kt:283`). Fix: background or lazy init.
2. MEDIUM keyboard opening resizes the whole web view (`MainActivity.kt:211-222` plus `Keyboard.resize: "native"`).
3. No Android SDK or emulator on this Mac; installing one needs the owner's OK.

Windows/Linux, Tauri (`claude/desktop-tauri` / PR 65):
1. HIGH `block_on(library.open())` and `reminders.load()` before the window exists (`src-tauri/src/lib.rs:1440, 1474`).
2. LOW blocking reads and per-request `canonicalize` in the asset handler (`lib.rs:1295-1304`); full library scan every
   30 s (`library/watch.rs:18`).

Windows, Electron (`claude/windows-electron-4ed862` / PR 58):
1. HIGH (memory) Quick Add creates a second full renderer at launch (`src/main.ts:1237`, `:714-743`); make it lazy.
2. HIGH (memory) a hidden runner window per non-open place, kept forever (`main.ts:600-614`).
3. MEDIUM background throttling off for local-mode windows (`main.ts:236-238`); LOW `sendSync("shell:bootstrap")` in
   the preload (`preload.ts:22`); full scans on focus and every 30 s (`main.ts:1218`, `library/watch.ts:70`).

Headless measurement: iOS via `xcrun simctl` + `xctrace` App Launch + `footprint` (trends only); Mac XCTest
`measure {}` only, since launching the app takes focus (owner's OK needed); Tauri/Electron memory via
`apps/desktop/scripts/measure.mjs` on CI.
